# 이별·죽음 이야기 막기 (내용 기준) — 짧은 설계

2026-11-17. 저장소 둘(Backend_Mainpage, AI_worker)과 API 스펙을 같이 고친다.

## 왜

이별·죽음 동화에서 "몸이 굳었어요", "죽었어요"처럼 아이가 하지 않을 말이 나온다 (11/3 회의, Backend#37). 품질을 맞출 때까지 이 주제로는 만들지 못하게 한다. 프론트는 '이별 · 죽음' 칸을 이미 잠갔다. 그런데 다른 주제를 고르고 내용에 이별·죽음을 쓰면 그대로 만들어진다. 서버도 `SEPARATION` 저장을 막지 않는다 (#37은 닫혔지만 코드는 없다).

## 목표 / 안 할 것

- 목표: 주제 칸과 상관없이, 부모 글의 **내용**이 이별·죽음이면 동화를 만들기 전에 막는다. 나중에 다시 열 때는 코드를 고치지 않고 설정값만 바꾼다.
- 목표: API로 `category: SEPARATION`을 보내도 서버가 거절한다 (#37).
- 안 할 것: 프론트 수정 (기존 '다시 쓰기 안내' 화면을 그대로 쓴다). 이별·죽음 이야기 품질 고치기.
- 실패로 볼 것: 이혼이 아닌 '가족의 변화'(동생, 재혼 등), 이사·새 어린이집, 잠깐 떨어지는 일까지 막히는 것. 막힌 부모가 위기 신호 횟수가 쌓여 차단(BLOCKED)되는 것.

## 고른 방법: A (사용자 선택)

|---|---|---|
| **A. AI 판단에 이별·죽음 표시 추가** (선택) | AI 호출이 늘지 않음. 맥락으로 판단. 판단하는 모든 곳을 덮음 | AI·Spring·스펙을 같이 고침 |
| B. SENSITIVE를 전부 막기 | Spring만 고침 | 이혼·입원·재혼·지나간 사고까지 막힘 |
| C. 낱말 목록 | 단순함 | "무지개다리"는 놓치고 "배고파 죽겠어"는 잘못 걸림 |

## 설계

**어디까지가 이별·죽음인가** *(Claude 제안, 확인 필요)*
- 막는다: 사람·동물의 죽음(곧 떠날 것 같은 것 포함), 이혼·별거, 가족과 오래(몇 달 넘게) 떨어져 지내는 것(해외 근무, 장기 입원으로 못 만남 등)
- 막지 않는다: 이사·전학·졸업으로 친구와 헤어지는 것('새로운 환경' 주제의 중심), 출장·등원처럼 잠깐 떨어지는 것, 가족의 병 자체(떨어져 지내는 게 중심이 아니면)

**AI 워커**
- `SafetyJudgement`·`SafetyResult`에 `topic: "separation" | null`을 더한다. level과는 따로 매긴다 (이별·죽음은 보통 SENSITIVE지만, 아이 탓으로 돌리면 REVISE이면서 topic도 separation).
- `safety_check.md`에 위 경계와 예를 넣는다. 완성 본문(`output`)에서도 topic을 매긴다.
- 인터뷰 답변: Spring이 요청에 `blocked_topics`를 보내고, 판단한 topic이 그 안에 있으면 REVISE·CRISIS처럼 답을 받기 전으로 되돌린다 *(Claude 제안: 막을 주제 목록을 Spring 설정 한 곳에만 두려고)*.
- mock: 글에 `[[SEPARATION]]`이 있으면 topic separation.
- 평가 사례 추가: 다른 주제 칸 + 죽음 내용, 이혼, 해외 근무, 이사(막지 않음), 출장(막지 않음), "배고파 죽겠어"(막지 않음).

**Spring**
- 설정 `firstory.story.blocked-topics=SEPARATION` (비우면 다시 열림). 상황 분류 `SEPARATION`과 AI topic `separation`에 같이 쓴다.
- 상황 저장에서 `category`가 막힌 주제이면 400 `CATEGORY_UNAVAILABLE` "지금은 이 주제로 만들 수 없어요".
- 이미 `SEPARATION`으로 저장된 만들던 동화는 인터뷰 시작과 만들기에서도 같은 오류 *(Claude 제안)*.
- `SafetyGuard`: topic이 막힌 주제이면 level보다 먼저 `ASK_REVISE`를 내고, 입력은 저장하지 않는다. reason은 AI 문장이 아니라 Spring이 정한 고정 문구로 보낸다("지금은 이별이나 죽음을 다루는 이야기는 만들 수 없어요. 다른 이야기로 바꿔 써 주세요." — 문구는 PM 확정 전). `SafetyFlag`를 남기지 않아서 REVISE 횟수에 들어가지 않는다. 다만 CRISIS면 CRISIS가 먼저다 (아이 안전이 우선).
- 결과 판단: 완성 본문의 topic이 막힌 주제이면 기존 결과 위기 신호처럼 실행·동화 FAILED(`OUTPUT_UNSAFE`)로 처리하고, 부모는 다시 시도할 수 있다 *(Claude 제안)*.
- Swagger 에러 코드, `docs/frontend/screens.md`, `fake-ai.md`(`[[SEPARATION]]`), API 스펙 4장에 반영한다.
