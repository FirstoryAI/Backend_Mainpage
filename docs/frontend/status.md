# 지금 되는 것과 안 되는 것

기준: 태그 `v0.1.0-frontend` (가짜 AI).

## 되는 것

[screens.md](screens.md)의 화면 전부가 local(가짜 AI)에서 끝까지 동작한다.

- 가입(문자 인증, 고정 인증번호 `000000`), 로그인·로그인 유지, 로그아웃, CSRF
- 내 정보: 비밀번호·휴대폰 변경, 문자 알림 동의, 탈퇴, 아이 프로필 추가·수정·호칭 변경·삭제
- 동화 만들기 CRT-01~06, 인터뷰(질문 1~5개), 분위기 선택 ST-04, 위기 신호 분기(다시 쓰기, 차단 ST-05)
- 생성 진행 GEN-01, 실패 ST-03과 다시 시도, 미리보기 REV-01, 그림(실제 PNG), 다시 만들기 REV-02(3가지 범위, 쪽 선택), 버전 목록·되돌리기, 확정 REV-04
- 홈 HOME-01, 서재 LIB-01(탭, 페이지), 상세·삭제 LIB-02
- 대화 가이드 GDE-01, 함께 읽기 RD-01~03(이어 읽기, 대화 버튼, 다 읽음)
- 실패 흉내: 생성 실패, 그림 한 장 실패, AI 장애, 결과 위기 신호 ([fake-ai.md](fake-ai.md))

## 아직 안 되는 것

| 항목 | 지금 | 프론트 영향 |
|---|---|---|
| 진짜 AI | 가짜 AI만. 동화 내용은 항상 같은 샘플 | 없음. 응답 모양과 흐름은 같다. 속도와 질문 수는 가짜가 흉내 낸다 |
| 실제 문자 발송 | 서버 로그로만 찍힌다. local 인증번호는 `000000` | 없음 |
| S3 파일 저장소 | 서버 폴더(`data/storage`)에 저장 | 없음. 그림 주소(`imageUrl`)는 그대로 유지된다 |
| 배포 | 개발 서버(Railway, dev 프로필: 가짜 AI, 인증번호 `000000`, Swagger) | 주소는 배포 후 따로 공유한다. 운영 주소는 아직 없다. 붙이는 방법은 `docs/deploy/railway.md`의 "쿠키와 프론트" |
| 상황·반응·감정 선택지 API | 없음. 아이 선택지(`GET /api/children/options`)만 있다 | CRT-01·02 버튼 문구는 [screens.md](screens.md)의 코드에 맞춰 임시로 프론트에 둔다. 필요하면 백엔드에 요청 |
| 웹 푸시 | 2차 범위 | 완성 알림은 문자(동의한 경우)뿐 |
| 카카오 로그인 | 하지 않음 | 이메일 + 비밀번호만 |
| 삭제한 동화·탈퇴 회원의 데이터 실제 파기 | 소프트 삭제만 | 없음 (API에서는 이미 안 보인다) |

## 바뀔 수 있는 것 (주의)

- **화면 문구 label들**: 서버가 내려주는 값을 쓰면 서버만 고치면 된다.
- **상담 기관**: 프론트 쪽 문구라 PM 확정 후 프론트가 고친다.
- **알림 문구**: 서버 쪽. 프론트 영향 없음.
- 오류 `message` 문장: 다듬어질 수 있다. 분기는 항상 `code`로 한다.
